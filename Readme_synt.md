# clean_VKR-feature-synthetic-data-mode

## env_synthetic
Директория для синтетических данных. Для соблюдения порядка почти во всех поддиректориях реализован приницп разделения на графики. 
На момент составления этого файла есть 3 графика: 3х2х3х1, 4х2, 5х2.  
### data
#### drivers.json

*подпапки 3х2х3х1, 4х2, 5х2*

Директория с табелями на каждый месяц (например, "drivers_april.json") формата 
```yaml
- month
- year
- days_in_month
- drivers:
     -  tab_number
     -  schedule
     -  mode
     -  shift_start
     -  shift_end
     -  days:
        - day
        - value
```

#### results

*подпапки 3х2х3х1, 4х2, 5х2*

Директория, в которой находятся распределения планировщика формата json. 
Промежуточное звено: scheduler -> results -> excel. Имеет формат
```yaml
- date: 
    - date
    - route
    - roster:
        - tram_number
        - shift_1:
            - driver
            - warnings
        - shift_2:
            - driver
            - warnings
        - issues
```


#### tabeles_2026_generated

*подпапки 3х2х3х1, 4х2, 5х2*

Табели для каждого месяца 2026 года в формате .xlsx. Сформированы с помощью файла **clean_parsing_tabeles.py**

#### absences.json
Информация об отсутствующих формата 

```yaml
- driver_id
- type
- from
- to
- comment
```

#### norms.json 

#### norms_2026.json 
Нормы работы на каждый месяц для 5х2 (40h) и 4х2 (33h)

#### schedule.json
Расписание формата
```yaml
- маршрут
- день
- трамваи:
  - номер
  - смена_1:
      - отправление
      - прибытие
  - смена_2:
      - отправление
      - прибытие
```

#### Приложение №1 График 4х2.xlsx
Синтетические данные графики водителей без болезней и отпусков на 1 месяц 
#### Приложение №2 График 5х2.xlsx
Синтетические данные графики водителей без болезней и отпусков на 1 месяц
#### Приложение №3 График 3х2х3х1.xlsx
Синтетические данные графики водителей без болезней и отпусков на 1 месяц 

### history
Это память системы. Служит для того, чтобы понимать ситуацию на первый день следующего месяца. 
Поле end_dt: **2026-02-23T14:08:00** означает, что смена закончилась 23.02.2026 в 14:08:00

## src

Основная директория

### analytics

Директория для файлов, собирающих данные для ответа на вопросы

- driver_counter.py - скрипт для подсчета водителей. 
Берет данные из env_synthetic/data/results и помещает водителей в множество, 
на выходе число уникальных водителей за выбранный в конфиге срок 
- kpi_report.py - скрипт для вывода лидеров и аутсайдеров по времени работы

### api
Код сервера

### core
Логика
- generate_history_TEMP - создание истории на срок с 24.12.2025 по 31.12.2025 для того, 
чтобы 01.01.2026 был реальный отдых


- _manage_absence.py_ - управление отсутствующими


- _run_simulation.py_ - запуск симуляции


- _scheduler.py_ - планировщик
  - Что делает: содержит бизнес-логику — считает нагрузку в часах, пытается расставить конкретных водителей на смены.
  - Зачем: отвечает на главные вопросы: "Сколько нужно людей?" и "Кто завтра выйдет на маршрут?"


### db
База данных

### experiments
Директория для экспериментов, нацеленных на минимизацию ручного труда

- experiment_runner.py - запускает эксперименты для всех графиков и разных типов отсутствий (для работы по кейсам). 
На выходе количество водителей в том или ином случае

### generate_reports
Генераторы отчетов
- _generate_schedule_book.py_ - создание файла, в котором описано, какой водитель на какую смену вышел. 
Моделируется на 1 маршрут, на 1 месяц


- _generate_summary_report.py_ - создание сводного отчета формата .xlsx

### parsers
Парсеры и вспомогательные функции

- _clean_report.py_ - очистка принтов и логов от эмодзи

- _tabeles_on_all_year.py_ - чистая генерация **табелей** формата .xlsx с учетом праздничных дней для целого года на основе табеля одного месяца
  - Исходный файл: data/tabeles_2026/february_2026.xlsx
  - Создает файлы: data/tabeles_2026/. Табели на все месяцы, кроме февраля
  - Актуальная версия


- _parsing_schedule.py_ - преобразует **расписание** формата .xlsx в .json
  - Исходный файл: data/data.xlsx
  - Создает файл: data/schedule.json
  - Актуальная версия


- _parsing_tabel.py_ - преобразует **табель** формата .xlsx в .json
  - Исходные файлы: data/tabeles_2026/april_2026.xlsx
  - Создает файлы: data/drivers_json/drivers_april.json
  - Актуальная версия


- _sync_missing_drivers.py_ - синхронизирует список водителей из табеля. 
Если код нашел водителей, которых нет в закреплении маршрутов, добавляет их к маршруту ANY
Временный файл. Возможно, еще пригодится

### prepare_data
- _database.py_
  - Что делает: загружает JSON-файлы (водители, расписания, закрепления) в память и связывает их между собой.
  - Зачем: создает единую "базу данных", чтобы другие части кода не лезли в файлы напрямую.

- _models.py_
  - Что делает: описывает структуру данных (как выглядят водители, маршруты, смены) через Pydantic-модели.
  - Зачем: чтобы Python понимал, какие поля есть в JSON-файлах, и проверял их корректность при загрузке.
